# Personal Expense Tracker — Case 02

MVP завершён: операции, категории, месячный бюджет, Dashboard, фильтры периодов и категорий, KPI, группировка расходов и простые графики через локальный repository. Stage 5 acceptance выполнен.

Стек: Next.js 16.3.4 (App Router, Turbopack), React 19.2.8, TypeScript 6.0.3, Tailwind CSS 4.3.3. Проверено на Windows, Node.js 22.23.1 и npm 10.9.8. Версии зависимостей зафиксированы в `app/package.json` и `app/package-lock.json`.

## Запуск

В PowerShell:

```powershell
Set-Location 'E:\Prompt\Freelance\Trecker\Case_02_Personal_Expense_Tracker\app'
npm.cmd ci
npm.cmd run dev -- --hostname 127.0.0.1
```

Открыть <http://localhost:3000>. Главная страница показывает Dashboard; разделы `/transactions`, `/categories` и `/budget` доступны через навигацию.

Production:

```powershell
npm.cmd run build
npm.cmd run start -- --hostname 127.0.0.1
```

Переменные окружения по-прежнему не нужны; `app/.env.example` фиксирует это. Supabase и авторизация не подключены. При проблеме проверки сертификата npm в этой Windows-среде помогло `$env:NODE_USE_SYSTEM_CA='1'` на Node.js 22.23.1; проверка TLS не отключалась.

## Проверки

Из `app/`:

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run test:browser
```

- `check`: ESLint без предупреждений, `next typegen` и TypeScript, затем 37 unit-тестов через Node test runner/tsx.
- `build`: обязательная отдельная production-сборка. Next.js 16 не запускает линтер автоматически.
- `test:browser`: 14 Playwright-тестов production-сборки в headless Microsoft Edge. Сервер запускается и останавливается самим тестом на `127.0.0.1:3212`; этот порт должен быть свободен. Тест перезапускает собственный сервер и отдельный браузерный профиль в `app/test-results/`, не затрагивая личный профиль браузера.
- Для другой среды можно задать `$env:PLAYWRIGHT_CHANNEL='chrome'`, если Chrome установлен. Фактически проверен Edge.

## Пользовательские сценарии Stage 3

- **Операции:** нажмите «Добавить операцию», выберите доход или расход, введите доллары (например, `12.50` или `12,50`), дату и необязательное описание. Для расхода обязательна категория. Внутри сохраняются целые центы.
- **Редактирование:** кнопка в записи открывает заполненную форму. Разрешено менять дату, сумму, описание, категорию и тип; смена типа переносит запись между доходами и расходами без дублирования. «Отмена» закрывает форму без записи.
- **Удаление:** отдельный диалог показывает тип, сумму, дату и описание. Начальный фокус на «Отмена»; Escape также отменяет. Удаление происходит только после «Подтвердить удаление» и успешного repository.save.
- **Категории:** добавление, переименование, архивирование и восстановление. Названия уникальны без учёта регистра и пробелов по краям, включая архив. Переименование отражается в истории. Архивную категорию можно сохранить при редактировании её прежнего расхода, но нельзя выбрать для нового.
- **Бюджет:** выберите календарный месяц, задайте общий лимит в USD и сохраните. Повторная запись обновляет бюджет этого месяца; ноль отличается от отсутствующего бюджета. Список сохранённых месяцев позволяет открыть старый бюджет. Суммы расходов и аналитика на этом экране пока не выводятся.
- **Ошибка записи:** введённая форма остаётся открытой, прежние сохранённые записи не заменяются. После устранения запрета/квоты можно повторить сохранение. При конфликте revision кнопка «Повторить загрузку» читает актуальные данные и сбрасывает открытую форму; автоматического перезаписывания чужой версии нет.

Несохранённые формы не являются черновиками: отмена, навигация на другой раздел, перезагрузка или повторная загрузка сбрасывают их. Все операции выводятся по убыванию даты, без фильтров и пагинации на этом этапе. Форма использует стандартный календарь браузера: отображение даты зависит от его локали, сохранение всегда YYYY-MM-DD.

Проверены production-сценарии CRUD, валидация, категории, бюджет, пустые состояния, отказ записи, конфликт revision, Dashboard и согласованность KPI с графиками. На ширинах 320/390/768/1280 px проверено отсутствие горизонтального переполнения; Dashboard проверен в production на 390 px. Скриншоты мобильной формы и desktop-списка сохраняет Playwright в `app/test-results/`.

## Данные и расчёты

Локальные данные записываются в `localStorage` под ключом `case02.personal-expense-tracker`. Формат: `{ schemaVersion: 1, revision, ledger }`. Данные доступны только в том же браузерном профиле и origin (протокол, хост, порт). `localhost` и `127.0.0.1`, а также разные порты используют разные хранилища.

Перезапуск сервера и обычное закрытие браузера не удаляют данные. Очистка данных сайта, удаление профиля и завершение приватного режима могут удалить их. Между устройствами синхронизации нет; данные не шифруются приложением.

При первом запуске пустого хранилища автоматически записываются синтетические демоданные с фиксированными датами и ID. Повторная загрузка не перезаписывает существующие данные, даже если списки операций пусты. Повреждённая запись, неизвестная версия, запрет доступа или переполнение хранилища приводят к сообщению об ошибке; автоматического сброса нет.

Для отдельной чистой демонстрации используйте новый браузерный профиль. Удаление ключа вручную в DevTools сбросит все локальные записи этого кейса; после перезагрузки seed создастся заново.

## Архитектура и ограничения этапа

- `app/src/domain/`: сущности, runtime-валидация, денежные и календарные функции, расчёты. Нет зависимостей от UI, browser API или хранения.
- `app/src/data/repository.ts`: асинхронный контракт чтения/сохранения; `local-storage-repository.ts` реализует его.
- `app/src/data/browser.ts`: точка выбора адаптера. Будущий Supabase реализует тот же контракт; доменная логика остаётся прежней.
- `app/src/data/demo.ts`, `initialize.ts`: воспроизводимые данные и безопасная однократная инициализация.
- `app/src/domain/commands.ts`: неизменяющие исходный снимок команды операций, категорий и бюджета; ошибки валидации привязаны к полям формы.
- `app/src/components/ledger-provider.tsx`: общий клиентский снимок, блокировка повторной записи, вызовы существующего repository; UI обновляется после успешного сохранения.
- `app/src/app/` и `app/src/components/`: маршруты и mobile-first формы/списки.

Предполагаются один локальный пользователь, USD, один общий бюджет на месяц и работа в одной вкладке. Проверка revision отклоняет устаревшие сохранения, но localStorage не даёт атомарной транзакции между независимыми вкладками; одновременное редактирование в нескольких вкладках пока не поддерживается.

Не реализованы: Supabase/Auth, категорийные бюджеты, экспорт, AI, банковские интеграции, синхронизация между устройствами и финальная визуальная полировка.

## Netlify deployment

Для deployment используется минимальный `netlify.toml` с `base = "app"` и `npm run build`; legacy `@netlify/plugin-nextjs` и static publish directory не используются. Production site: <https://case02-personal-expense-tracker.netlify.app>. Доступность URL зависит от настроек Netlify account-level SSO.

Публикация не меняет модель хранения: production-приложение по-прежнему хранит операции только в localStorage браузера и не синхронизирует их между устройствами или пользователями.
