В браузерном тесте существующая запись специально изменяется через localStorage (без добавления тестового API или CRUD-экрана), затем сравнивается побайтно после reload и полного перезапуска браузера/сервера. Сохранение изменённого Ledger через `repository.save` отдельно проверено модульным тестом с созданием нового экземпляра адаптера. Проверка выполнена при неизменном origin и профиле.

Модульные тесты покрывают:
- точный перевод десятичных строк в центы, недопустимые суммы и переполнение;
- реальные даты, високосные годы, границы недель/месяцев/года, включение обеих границ и одинаковые результаты в четырёх часовых поясах;
- доходы, расходы, денежный баланс, остаток бюджета, отсутствие/ноль бюджета, перерасход и пустые периоды;
- пересчёт после изменения/удаления исходных записей;
- валидность владельца и категории, архивную категорию, повторные ID и бюджет на один месяц;
- однократный seed при конкурентных вызовах, сохранение пустых списков, повторную загрузку, stale revision, ошибку квоты и повреждённые данные.

## Версии и документация

Фактически установлены Next.js 16.3.4, React/React DOM 19.2.8, TypeScript 6.0.3, Tailwind 4.3.3, Playwright 1.63.0. Среда: Windows, Node.js 22.23.1, npm 10.9.8. Использована документация из самого установленного пакета Next.js; перечень руководств — в `architecture.md`.

При установке npm первоначально не доверял цепочке сертификата. Повтор с системным хранилищем сертификатов (`NODE_USE_SYSTEM_CA=1`) прошёл; TLS не отключался. npm сообщил 0 известных уязвимостей при установке. Это не отдельный security-аудит. npm также предупредил о прекращении поддержки установленной ESLint 9.39.5; текущая конфигурация Next.js с ней работает, проверка линтера прошла без предупреждений.

## Принятые допущения и ограничения

- Локальное хранение, без Supabase и без авторизации — явное решение пользователя.
- USD и два десятичных знака; один локальный пользователь и общий месячный бюджет.
- Неделя начинается в понедельник; дата не содержит времени и часового пояса.
- Одна активная вкладка: revision защищает от устаревших последовательных записей, но атомарности между вкладками localStorage не предоставляет.
- Смена origin/профиля открывает другое хранилище. Очистка данных браузера удаляет записи; облачного восстановления нет.
- Схема v1 отклоняет неизвестные версии без миграции. Будущий Supabase должен реализовать тот же асинхронный контракт с атомарным сохранением и проверкой владельца.
- Финальная мобильная/визуальная приёмка ещё не проводилась; браузерный сценарий восстановления запускался с viewport 390×844.
